# FAST – تعز إكسبرس

مشروع Flutter مع Supabase وملفات Backend أولية.

## بناء Android عبر Codemagic
- ملف إعداد البناء: `codemagic.yaml` في جذر المشروع.
- معرف تطبيق Android: `com.taizexpress.taiz_express`.
- أذونات Android المضافة: الإنترنت، حالة الشبكة، الموقع التقريبي والدقيق.
- يبني Workflow ملف APK من نوع Release ويعرضه ضمن Artifacts.
- يقوم Workflow عند الحاجة بإنشاء ملفات Gradle Wrapper الرسمية من قالب Flutter أثناء البناء؛ لذلك لا تحذف خطوة إعداد Gradle Wrapper من `codemagic.yaml`.
- التوقيع الحالي للتجربة باستخدام debug signing. إعداد مفتاح release الحقيقي مطلوب قبل النشر التجاري.

## إعداد Supabase
عنوان المشروع ومفتاح العميل موجودان في `lib/main.dart` كما كانا في الأرشيف الأصلي. لا تضع مفتاح `service_role` في التطبيق. يجب تفعيل RLS وإنشاء سياسات مناسبة لكل جدول قبل نشر التطبيق.

## تقرير الفحص
راجع `PROJECT_AUDIT_AR.md` لمعرفة نقاط القوة والضعف والنواقص، وما تم فحصه وما لم يتمكن الفحص من تأكيده.

**تنبيه:** لم يتم تعديل `lib/` أو SQL في هذه النسخة. لم يتم تأكيد بناء APK فعلياً لعدم وجود Flutter SDK في بيئة الفحص، لذلك يجب اعتبار أول Build على Codemagic اختبار تحقق وليس دليلاً مسبقاً على خلو التطبيق من أخطاء Dart أو قاعدة البيانات.
